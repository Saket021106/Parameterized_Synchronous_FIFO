Why a FIFO?

Almost every real system has two sides that produce and consume data at different, uneven rates: a fast producer feeding a slower consumer, a bursty sensor feeding a steady processing pipeline, or two blocks that simply aren't ready at the same moment. A FIFO (first-in, first-out) buffer absorbs that mismatch. Data goes in in order, comes out in the same order, and the two sides only need to agree on a handful of handshake signals rather than on timing.

This project implements a synchronous FIFO, meaning both the write side and the read side share one clock. It is built as a circular buffer of registers with independent write and read pointers and a separate counter that tracks occupancy directly, which is what lets full and empty be computed with no ambiguity even as the pointers wrap around the array.

Parameterized

Word width (DATA_WIDTH) and depth (REGS) are both compile-time parameters, so the same RTL produces a 4-, 8-, or 16-entry FIFO of any width without any code changes.

Circular, not shifting

Writes and reads move independent pointers around a fixed array instead of shifting data physically, which keeps every operation a single-cycle, constant-cost register write.

Unambiguous status

A dedicated count register, one bit wider than needed to index the array, removes the classic pointer-equality ambiguity between full and empty.

Circular Buffering and Occupancy Tracking

Two pointers, one array

write_ptr advances every time a write is accepted; read_ptr advances every time a read is accepted. Each is $clog2(REGS) bits wide and wraps back to zero after reaching REGS - 1, which is what turns a linear array of registers into a circular buffer: the oldest unread entry is always at read_ptr, and the next free slot is always at write_ptr.

Why a separate counter

A common FIFO pitfall is trying to distinguish full from empty using only the pointers, since both conditions can make write_ptr == read_ptr true. This design sidesteps the problem entirely with an explicit count register, $clog2(REGS)+1 bits wide so it can represent every value from 0 up to and including REGS. full and empty are then simple combinational comparisons: full = (count == REGS), empty = (count == 0).

Guarded reads and writes

A write is only accepted when wr_en is asserted and the FIFO is not full; a read is only accepted when rd_en is asserted and the FIFO is not empty. Both guards are checked independently, so a write attempted while full, or a read attempted while empty, is silently ignored rather than corrupting the pointers or the stored data.

Correct simultaneous read and write

When a read and a write are both accepted on the same clock edge, count must not change, because one entry leaves and one enters. The RTL expresses this directly: count increments only on a write-without-read, decrements only on a read-without-write, and is left alone whenever both happen together. This is a detail that is easy to get wrong with a simpler up/down-counter description, and the testbench specifically exercises it.

From Specification to Verified RTL

  1. Specify the interface. Decide on a simple enable-based handshake (wr_en, rd_en) rather than a ready/valid protocol, plus status flags (full, empty) for the surrounding logic to poll.
  2. Choose the occupancy strategy. Select an explicit counter over pointer-comparison tricks, trading one extra register for a design that is obviously correct and easy to verify.
  3. Size everything from parameters. Derive pointer width as $clog2(REGS) and counter width as $clog2(REGS)+1, so depth and width changes never require touching a bit range by hand.
  4. Write the RTL. One always_ff block handling reset, write, read and count update, plus two continuous assignments for the flags.
  5. Build a parameter-driven testbench. Write the test sequence once, in terms of DATA_WIDTH and REGS, so it is depth- and width-agnostic by construction.
  6. Instantiate the same test three times. Run it unmodified at 4×4, 8×8 and 16×16 inside one top-level testbench, so all three depths are verified in a single simulation.
  7. Exercise every corner case. Reset, read-while-empty, write-until-full, write-while-full (must be ignored), full read-back in order, pointer wraparound, and simultaneous read/write on the same edge.

SystemVerilog Overview

sync_fifo #(DATA_WIDTH, REGS)

The only module in the design. A packed array data[0:REGS-1] holds the entries; write_ptr, read_ptr and count are the only state besides the stored data itself.

Status flags

full and empty are plain assign statements driven by count, so they are always current and never need their own state machine.

The core sequential block

always_ff @(posedge clk) begin
  if (rst) begin
    write_ptr <= '0; read_ptr <= '0; count <= '0; data_out <= '0;
  end else begin
    if (wr_en && !full) begin
      data[write_ptr] <= data_in;
      write_ptr <= (write_ptr == REGS-1) ? '0 : write_ptr + 1'b1;
    end
    if (rd_en && !empty) begin
      data_out <= data[read_ptr];
      read_ptr <= (read_ptr == REGS-1) ? '0 : read_ptr + 1'b1;
    end
    if ((wr_en && !full) && (!rd_en || empty))       count <= count + 1'b1;
    else if ((rd_en && !empty) && (!wr_en || full))  count <= count - 1'b1;
  end
end

Both the write and the read branches are evaluated every cycle, independently of each other, which is exactly what allows a simultaneous read and write to be accepted together: the count update is the only place the two interact.

What each signal group shows

data_in

Steps through the exact values the testbench assigns each phase; it is a stimulus signal, not an output, so it changes the instant the testbench writes it, ahead of the clock edge that captures it.

wr_en, rd_en

Each stays high for a run of consecutive cycles rather than pulsing per-transfer, which is what lets several writes or reads happen back to back.

full, empty

Both are purely combinational on count, so they update in the same cycle count does — there is no extra registered delay to account for when reading the trace.

data_out

Registered, so it updates one cycle after the rd_en that captured it, and it holds its last value, including through phases where no read is happening.

How this validates the design

Correctness of ordering: every read-back phase returns values in the exact order they were written. Correctness of flags: full and empty transition at exactly the write or read that should cause them to, never early or late. Correctness of wraparound: reused array slots hold the newly written values, not stale ones. Correctness of simultaneous access: count stays flat exactly when a read and a write both occur. Correctness of parameterization: all three widths and depths reach the same qualitative result at the same relative points in their own timelines, confirming the RTL scales cleanly.
